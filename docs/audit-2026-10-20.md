已修复的问题如下。表中“记录”代表在真实历史中找到相应证据，“复现”代表新增或扩展测试确认原实现失败。

| 缺陷与影响 | 依据 | 修改 |
| --- | --- | --- |
| 入口路由发送该 skill 全部 `contains` 关系，几千条无关边占用输入与时间 | 记录＋复现 | 仅保留指向本批候选义务的归属边；前置关系仍保留外部端点信息，候选卡不裁剪 |
| `inputChars` 是全候选视图，不能代表实际分批请求；快照未保存关系，无法完整重建判断输入 | 记录＋复现 | 每次模型尝试记录实际 `inputChars`，决策增加累计 `requestChars` / 最大 `maxRequestChars`；证据保存本次相关关系 |
| 规则重编译但 ID 不变时，工具缓存继续复用旧判定 | 复现 | 缓存键包含图版本、模型设置、门槛、作用域和触发事件；仅工具边界入缓存 |
| 两个相同调用同时判断时，各自消耗一次软拦截 | 复现 | 判定完成时重新检查并领取本回合拦截资格，同一调用并发也只拦一次 |
| 并发保存设置相互覆盖，甚至拼接成非法 JSON | 复现 | 按文件串行读取合并，通过临时文件原子替换 |
| 配置读取失败时，面板保存会拿空对象覆盖原文件 | 复现 | 拒绝覆盖损坏配置；根节点不是对象也显式报错 |
| 清空设置仍保留旧运行值，profile 优先级在保存前后不一致 | 扩展回归 | 从默认值、操作员文件、原始 profile 重新解析，清空与重启一致 |
| HTTP 400 的 `membership rpm limit exceeded` 被分类成未知错误，不能触发限流降压 | 记录＋复现 | 识别 RPM / TPM 限流信息，复用已有并发退避机制 |
| 一个义务有多个前置条件时，只检查最后一个，失效前置的下游可能错误保留 | 复现 | 遍历全部前置依赖并缓存遍历结果，结果不依赖关系顺序 |
| 编译模型使用 `entry` 作为义务 ID 时，与系统入口卡冲突 | 复现 | 预留入口 ID，义务自动使用唯一后缀，避免图自环及卡片覆盖 |
| 混用增量文本和完整文本块的模型响应会丢掉后续块 | 复现 | 按当前文本块补齐未流出的部分，最终结果和 `onDelta` 各保留完整内容一次 |
| 显式 workdir 遮蔽命令中的 cd；引号内空格、连续 cd 和 UNC 路径识别错误 | 复现 | 从 workdir 解析前导字面目录变更，保留路径中的空格；动态路径标注范围未知 |
| 同一操作成功后再失败，仍可能被计为连续失败 | 复现 | 相同操作成功时清除失败连续计数，普通成功读取不清除其他操作的失败 |
| 恢复会话丢失后台完成通知或 job_output 参数，已完成检查仍显示运行中 | 复现 | 恢复时保留后台参数并消费完成通知 |
| Windows 负数进程退出码可能被当成成功 | 复现；样本中未发现真实负数退出码 | 账本与后续轨迹识别带符号的非零退出码 |
| 宿主压缩历史后的 `surfaceOp: replace` 被当成新结果，重复计算编辑、失败和 skill 加载 | 记录＋复现 | 更新日志位置但不推进行为 / 证据水位，不再次消费执行副作用；后续轨迹也跳过替换事件 |

大输入的离线对比使用较早固定的 94 个证据快照，以及本机保存的编译分段重建关系图。其中原 `inputChars` 至少 500,000 的 26 个样本，平均由 **878,533** 字符降至 **334,907** 字符，约减少 **61.9%**。例如决策 `b768c4b4-d86d-4ad8-b960-889415eca238` 从 828,783 降至 257,737 字符。旧快照没有关系，重建使用当前缓存图，因此该数字是离线估算，不是同版本在线 A/B 延迟或 token 节省。独立回归还构造了 5,000 条归属边，确认单入口判断的提示词不再随全部子卡数膨胀，同时保留实际候选义务的归属与前置关系。

验证采用 `npm test`：203 项检查全部通过，包含原有单元、假宿主端到端、编译恢复、证据、调度与真实 Chromium 面板检查，加上 `tests/audit.mjs` 和并发 / 缓存回归；`git diff --check` 通过。主要缺陷先通过新增测试复现失败，再验证修改后的行为。离线审计工具还用多帧和截断尾帧验证，避免只读取压缩文件第一帧却误称完成扫描。

重复本机审计：

```powershell
node scripts/audit-records.mjs --out audit-summary.json
```

可用 `--home` 指向另一 DSH 数据目录，`--state-dir` 指向自定义插件状态目录。工具只读取记录、输出统计；不调用辅助模型，不执行会话中的命令。日志损坏或会话末帧未写完时返回非零退出码并列出未完整读取的位置。会话总事件包含历史替换，但加载次数与协议动作统计排除替换副本。

仍需区分以下限制与本轮已验证的修复：

- 目录很大时仍会检查全部可调用入口；关系去重改善输入体积，但完整证据本身仍可能很长，20 秒上限下不能保证所有判断完成。
- 保留的证据窗口不是无限历史。语义误判、编译漏抽取和长期任务遗漏还需要真实模型评估；本轮没有用缩短原文或降低置信门槛换取“通过”。
- 新增证据字段允许后续核验实际分批大小；本次采集的运行记录尚无 `requestChars` / 关系快照，不能据此声称运行实例已加载修改。应在适当的会话边界重新加载插件，再观察超时率、已回答比例与实际请求大小。
- 日志和配置的串行写入保障同一进程内一致性；多个独立 Harness 进程同时操作同一个目录仍没有跨进程锁。
- 旧式纯文本拦截不能可靠地升级成结构化执行状态；保留原记录作为历史，不把任意工具输出中的协议标签当作未执行证明。

当前 Desktop profile 指向本目录的 `index.js`；代码修改无需构建插件。本轮保留了运行会话，没有重启 Harness、修改真实配置或调用收费模型。现有工作区改动也保持未提交状态。
